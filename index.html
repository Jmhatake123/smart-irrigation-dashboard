Three physical zone profiles

A, B, and C remain the physical ESP1 zone identifiers. Crop profiles are dashboard planning notes only: the current ESP1 firmware does not read them to start or change an irrigation run.

Safe remote controls

The existing ESP1 firmware accepts only 5-second transfer/mixer tests and emergency stop from Firebase. ESP1 validates every request before it affects ESP2.

Transfer pump test

Existing ESP1 safe exercise: 5 seconds.

Tank mixer test

Existing ESP1 safe exercise: 5 seconds. This dashboard does not change inverter settings.

Booster test by destination

ESP1’s current remote command contract has no destination or solenoid field. No booster command will be sent until firmware support exists.

Emergency system stop

Immediately queues an ESP1 emergency-stop request. It is never blocked by the normal 10-second cooldown or by stale live telemetry. “Queued” is not physical-stop confirmation; wait for ESP1’s command status.

Forced irrigation / fertigation review

These forms validate a request and show a review only. The current ESP1 code has no remote forced-run command schema, so these actions are deliberately not sent to Firebase.

Forced irrigation

Reservoir capacity is not exposed by ESP1, so no capacity calculation is guessed.

Forced fertigation

Inputs are not submitted because ESP1 exposes no safe forced-fertigation Firebase command path.

Distribution valves / solenoids

The dashboard does not offer Valve A, B, or C buttons. The current ESP1 Firebase contract has no remote solenoid command or feedback, so showing manual valve controls would be misleading. Hardware/firmware support is required before those controls can exist.

ESP1 diagnostics

Actual diagnostics published by ESP1. Credentials, tokens, keys, and private service values are never displayed.
